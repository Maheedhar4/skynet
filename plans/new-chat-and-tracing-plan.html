skynet — Feature Plan

Two new features requested on top of the shipped app: F1 · New chat & Clear history (chat UI affordance) and F2 · Session tracing (OpenTelemetry for agent requests, in-app viewer + OTLP export). Decisions locked in with the owner on 2026-10-19.

F1: New chat resets + separate Clear-history action F2: In-app trace viewer F2: OTLP export to Jaeger/Grafana F2: Metadata-only spans by default

Where the code stands today

F1 — backend is already built

  • POST /api/session/new → ChatService.startNew(sid) — swaps in a fresh session, calls engine.forget(sid), rewrites the index. Old transcript file stays on disk.
  • ChatApiService.newSession() in the web app already works — it is simply never wired to any button.
  • F1 is therefore mostly UI wiring + one new clear-all endpoint.

F2 — no tracing exists yet

  • Only a console logger (apps/server/src/logger.ts).
  • @google/adk already pulls @opentelemetry/* transitively and ADK v2 is built on OTel — an OTel-native approach is natural and cheap.
  • The pipeline is small and explicit (http/app.ts → ChatService → engines → McpToolSource) — manual spans beat heavy auto-instrumentation here.

F1 — New chat + Clear history

Server

  • ChatService.clearHistory(sid) (apps/server/src/agent/chat-service.ts): delete every transcript JSON under dataDir/history/, reset index.json, then reuse startNew(sid) so the UI lands on a fresh empty session. Add a forgetAll() to the Engine contract (agent/engine-types.ts + both engines) so stale genai / ADK in-memory chats for other sids cannot resurrect deleted history.
  • POST /api/session/clear (apps/server/src/http/app.ts) → returns { ok: true, deleted: n, sessionId }.
  • Small util in data/files.ts: safe directory listing + unlink loop (0600 files, path-traversal-safe via the existing joinSecure).
  • The token store lives in a separate directory and is not touched — clearing chat history never logs connectors out.

Web

  • Header buttons in app.html / app.ts: + New chat (pill style mirroring the connect button) and Clear history… (subtle/danger styling, guarded by a confirm() dialog — irreversible).
  • Both disabled while chat.streaming().
  • New chat → existing newSession(), plus: clear pendingGateId / buffered deltas, reset the message scroller.
  • Clear history → new clearHistory() method in ChatApiService → replace turns with the returned fresh session.
  • Styles in app.css, including the existing @media (max-width: 560px) mobile adjustment so three header buttons still fit.

F2 — Session tracing (OpenTelemetry)

SDK setup — new apps/server/src/telemetry/ module

  • tracer.ts — singleton NodeTracerProvider (guard against double registration; ADK ships its own OTel wiring). Resource service.name=skynet-server + engine/model attributes. Node SDK's async-hooks context manager lets spans nest correctly across the streaming async-generator chain with zero threading effort.
  • store.ts — a custom SpanExporter that appends finished spans to a bounded in-memory ring buffer (~2000 spans) as plain records: { traceId, parentSpanId, name, startedAt, durationMs, status, attributes }. This feeds the in-app viewer — no external infrastructure required.
  • OTLP/HTTP BatchSpanProcessor activates only when OTEL_EXPORTER_OTLP_ENDPOINT is set (Jaeger all-in-one on :4318, Grafana Tempo, Altitude, etc.).
  • Skip the Jaeger exporter (deprecated upstream) — OTLP is the single standard export path.

Content policy

Metadata only by default. Tool names, argument previews, durations, statuses, model, round numbers, gate decisions. Prompt/response text stays out of traces unless SKYNET_OTEL_CONTENT=1 opts in. Tokens/secrets are never traced; reuse of the existing redact() helper stays the rule.

Errors use recordException + status ERROR; a 'yes'/'no' gate answer appears as the gate-resolve span automatically.

In-app trace viewer (web)

  • GET /api/traces?session=&limit= in http/app.ts + query helpers in store.ts: traces grouped by traceId, sorted newest-first, spans flattened to waterfall rows.
  • New TracesService (Angular signals) + trace-drawer component under apps/web/src/app/components/trace-drawer/ (ts/html/css, dark theme vars matching app.css).
  • Collapsible right-side drawer, opened by a ⏱ Traces header button. Lists recent traces for the session; expanding one shows the waterfall: span name, duration bar, status color, attributes.
  • Fetch on open + manual refresh + optional 5s poll while open. Types via models.ts. Buttons disabled while streaming, like everything else.

Build order

  1. F1 server: clearHistory() + forgetAll() + POST /api/session/clear + files util.
  2. F1 web: header buttons, service methods, guard states, styles, mobile fit.
  3. F2 setup: telemetry module (provider, store exporter, OTLP switch), deps, init in src/index.ts before connector boot.
  4. F2 instrumentation: middleware → ChatService → engines → callTool; health endpoint field.
  5. F2 viewer: /api/traces → TracesService → trace-drawer UI.
  6. Verify: run the real flow — connect Zepto → search → add to cart → gated order (YES path) → inspect the trace waterfall end-to-end; plus OTLP smoke against local Jaeger.

Acceptance criteria

  • New chat resets the transcript instantly mid-session; no stale gate card or delta residue; works while connectors stay green.
  • Clear history (after confirm) deletes transcript files + index, makes the current and any other sid start fresh, and never touches token/auth data.
  • During streaming both actions are disabled — no mid-turn session swaps.
  • Trace drawer answers "what happened in this session?" with zero external infra: turn → rounds → tool calls → gate decision, all with durations.
  • With OTEL_EXPORTER_OTLP_ENDPOINT set, the same traces appear in any OTLP-compatible backend.
  • No prompt/response text in traces unless SKYNET_OTEL_CONTENT=1; no tokens anywhere.
  • Tracing off (SKYNET_OTEL=off) loses nothing but the viewer/export — chat behaves identically.

Risks & notes

  • ADK double registration — ADK is OTel-native; the provider setup registers once, globally, guarded (setGlobalTracerProvider only once), so ADK's internal telemetry merges into the same capture rather than conflicting.
  • Version alignment — OTel deps chosen to match versions already in the lockfile via @google/adk so npm workspaces dedupes to a single @opentelemetry/api instance.
  • Viewer persistence — the in-app store is memory-only; traces reset on server restart (acceptable for a local dev tool). A JSONL sink can be added later as a non-breaking follow-up.
  • Async context across streams — the chat pipe runs inside one request lifecycle; SDK's async-hooks context manager makes parent/child nesting automatic even across the async-generator + ReadableStream chain.
  • Mid-turn clear — clear-all is disabled while streaming, mirroring New chat, so the session swap can never race a running turn.
